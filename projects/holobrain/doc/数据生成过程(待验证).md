结论：这条数据链路分为两层。

1. `convert_hc_tj_mcap.py` 把每个 MCAP 转成一个 RODataset episode，真正写入 Arrow 的业务字段只有 `joints/actions/head/head_depth`。
2. `HcTjRODataset` 读取 Arrow，按“当前帧 + 未来 64 帧”采样关节序列，物化 DuckDB 元数据，并派生出 `imgs/depths/intrinsic/T_world2cam/joint_state/...` 等 HoloBrain 字段。

并没有套用 Agilex 数据集或 Agilex URDF。机器人结构来自命令行传入的 hc_tj URDF，训练配置也固定使用 [hc_tj_robot.urdf](/data/workspaces/RoboOrchardLab/hc_assets/hc_tj_description/urdf/hc_tj_robot.urdf)。

## 5. 多流时间同步

同步入口：

[_synchronize_source()](/data/workspaces/RoboOrchardLab/projects/holobrain/scripts/convert_hc_tj_mcap.py:639)

以每条 RGB 消息的时间戳为锚点，分别寻找最近的：

- 深度消息
- `joint_states`
- `joint_cmd`
- `joint_cmd_finger_right`
- `joint_cmd_finger_left`

容差为：

| 数据流 | 最大时间误差 |
|---|---:|
| 深度 | 50 ms |
| 关节状态 | 20 ms |
| 关节命令 | 20 ms |
| 左右末端命令 | 150 ms |

逻辑等价于：

```text
每条 RGB(t)
 ├─ nearest depth(t_depth), 误差 <= 50 ms
 ├─ nearest joint_states(t_state), 误差 <= 20 ms
 ├─ nearest joint_cmd(t_action), 误差 <= 20 ms
 ├─ nearest right finger(t_right), 误差 <= 150 ms
 └─ nearest left finger(t_left), 误差 <= 150 ms
             ↓
       形成一个训练帧
```

任一数据流超限，整条 RGB 帧被丢弃。RGB 时间戳最终成为该 Arrow 帧的：

```text
timestamp_min = timestamp_max = RGB timestamp
```

最近邻并不是插值：

- 不对关节角插值。
- 不对深度插值。
- 同一个低频样本可能被多个相邻 RGB 帧复用。
- 时间相等时按照较早时间戳优先。

## 8. RODataset 自动添加的索引字段

`DatasetPackaging` 会给每一帧自动添加：

```text
index
frame_index
episode_index
robot_index
task_index
instruction_index
timestamp_min
timestamp_max
```

代码位于：

[_extend_frame_with_index()](/data/workspaces/RoboOrchardLab/robo_orchard_lab/dataset/robot/packaging/_writer.py:169)

其中：

- `index`：整个 RODataset 的全局连续帧编号。
- `frame_index`：episode 内的帧编号，从 0 开始。
- `episode_index`：指向 DuckDB 的 episode。
- `robot_index`：指向 hc_tj URDF 元数据。
- `task_index`：指向任务元数据。
- `instruction_index`：指向语言指令元数据。
- `timestamp_min/max`：来自当前 RGB 时间戳。

Arrow 保存帧级数据，DuckDB 保存 episode/task/robot/instruction 元数据。这是 RODataset 的“双层存储”结构：

```text
Arrow
 ├─ joints/actions/head/head_depth
 └─ 各类 metadata index

DuckDB
 ├─ Episode
 ├─ Task
 ├─ Robot
 └─ Instruction
```

## 9. HcTjRODataset 如何读取这些数据

入口类：

[HcTjRODataset](/data/workspaces/RoboOrchardLab/robo_orchard_lab/dataset/hc_tj/hc_tj_ro_dataset.py:156)

### 9.1 关节窗口采样

`EpisodeChunkSampler` 为 `joints` 和 `actions` 采样：

```text
hist_steps 个历史帧 + pred_steps 个未来帧
```

在当前配置下：


```text

actions -> 长度 65 的 BatchJointsState 列表
```

而：

```text

```

仍然只取当前索引的一行。

## 10. 您列出的所有键如何产生

核心解析器是：

[_HcTjArrowDataParse](/data/workspaces/RoboOrchardLab/robo_orchard_lab/dataset/hc_tj/hc_tj_ro_dataset.py:47)

完整映射如下。

| 最终键 | 直接/派生 | 来源与逻辑 |
|---|---|---|
| `joints` | Arrow + 窗口采样 | `joint_states`，当前 1 帧加未来 64 帧的 `BatchJointsState` 列表 |
| `actions` | Arrow + 窗口采样 | `joint_cmd`，当前 1 帧加未来 64 帧的 `BatchJointsState` 列表 |
| `head` | Arrow | RGB JPEG、RGB 内参、畸变、`eye → zhi_Link` pose |
| `head_depth` | Arrow | 16UC1 PNG，使用 RGB 内参和同一相机 pose |
| `index` | 打包器生成 | 整个数据集中的全局 Arrow 行号 |

| `task` | DuckDB 物化 | `--task-name` 和 `--instruction` 形成的 Task |
| `robot` | DuckDB 物化 | `--urdf` 指定的 hc_tj URDF 全文 |
| `instruction` | DuckDB 物化 | `{"description": instruction}` |
| `text` | 读取时派生 | `instruction.json_content["description"]` |
| `imgs` | 读取时派生 | `head.sensor_data[0]` 经 `cv2.imdecode(IMREAD_COLOR)`；形状 `[1,H,W,3]` |
| `depths` | 读取时派生 | PNG 解码为 uint16，再除以 `depth_scale=1000`；形状 `[1,H,W]`，单位米 |
| `intrinsic` | 读取时派生 | `head.intrinsic_matrices[0]` 填入 4×4 齐次矩阵；形状 `[1,4,4]` |
| `T_world2cam` | 读取时派生 | 对 Arrow 中 `eye → zhi_Link` pose 求逆，得到 `zhi_Link → eye`；形状 `[1,4,4]` |
| `joint_state` | 读取时派生 | 对 65 个 `joints` 提取 position，得到 `[65,16]` |
| `master_joint_state` | 读取时派生 | 对 65 个 `actions` 提取 position，得到 `[65,16]` |
| `step_index` | 读取时派生 | 当前 episode 内的 `frame_index` |
| `step_index_in_chunk` | 读取时派生 | `hist_steps - 1`，当前配置为 0 |
| `task_name` | 读取时派生 | `task.name`，通常是 `hc_tj` |

1. `imgs` 虽然表示 RGB 相机数据，但 `cv2.IMREAD_COLOR` 的直接输出通道顺序是 BGR。
2. `T_world2cam` 中的 `world` 是历史字段名；对 hc_tj 来说这里的 world 实际指 `zhi_Link`。

## 12. 进入 HoloBrain 前的训练预处理

训练配置在：

[config_hc_tj_ro_dataset.py](/data/workspaces/RoboOrchardLab/projects/holobrain/configs/config_hc_tj_ro_dataset.py:157)

处理顺序如下。

### 12.1 `AddItems`

加入：

```text
T_base2world
joint_mask
joint_scale_shift
state_loss_weights
fk_loss_weight
```

其中：

- 14 个手臂维度的 `joint_scale_shift` 来自 hc_tj URDF 真实限位；
  两个二值末端维度固定使用 `[scale=0.5, shift=0.5]`。
- 每个关节的 scale/shift 为：

```text
scale = (upper - lower) / 2
shift = (upper + lower) / 2
```

- `T_base2world` 是 hc_tj URDF 零位姿下的 `base_link → zhi_Link`。
- 右臂 URDF 参数索引固定 `[5..11]`。
- 左臂 URDF 参数索引固定 `[13..19]`。

### 12.2 `SimpleStateSampling`

当前设置：

```python
use_master_gripper=True
use_master_joint=True
```

因此：

- 历史状态来自 `joint_state`，即 `joint_states`。
- 未来预测目标来自 `master_joint_state`，即 `joint_cmd`。
- `hist_joint_state` 形状为 `[1,16]`。
- `pred_joint_state` 形状为 `[64,16]`。
- episode 末尾不足 64 帧时复制最后动作，并把补齐位置的 `pred_mask=False`。

实现：

[SimpleStateSampling](/data/workspaces/RoboOrchardLab/robo_orchard_lab/dataset/horizon_manipulation/transforms.py:98)

### 12.3 图像增强和缩放

训练模式依次执行：

```text
RandomCropPaddingResize
Resize(dst_wh=(392,252))
ToTensor
```

它同时修改 RGB、深度和相机内参，保证裁剪/缩放后的内参仍与图像一致。

### 12.4 外参处理和投影矩阵

训练时：

```text
ExtrinsicNoise
    ↓
MoveEgoToCam(head)
    ↓
GetProjectionMat(target_coordinate="ego")
```

形成：

```text
T_base2ego
projection_mat
embodiedment_mat
```

其中 `head` 相机被作为 ego 坐标系。因为只有一个头部相机，ego 相机自身的投影关系经过坐标链组合后得到统一的相机几何表达。

### 12.5 关节噪声

`JointStateNoise` 给 14 个手臂关节加入 `[-0.02, 0.02]` 范围噪声，并因
`add_to_pred=True` 给未来动作施加相同偏移；两个二值末端维度不加噪声。

### 12.6 hc_tj URDF 正向运动学

`MultiArmKinematics` 使用真正的 hc_tj URDF：

```text
右臂关节参数：[5..11]
左臂关节参数：[13..19]

右臂链接：Link1_R ... Link7_R；末端链接：R_ban_Link
左臂链接：Link1_L ... Link7_L；末端链接：L_ban_Link
```

16 维输入按每臂“7 个关节 + 1 个末端状态”组织，手臂关节填入完整 URDF
关节向量，然后运行 `pytorch_kinematics.forward_kinematics()`。

每个关节最终表示为 8 维：

```text
[joint_angle, x, y, z, qw, qx, qy, qz]
```

形成：

```text
hist_robot_state: [1, 16, 8]
pred_robot_state: [64, 16, 8]
```

实现：

[MultiArmKinematics](/data/workspaces/RoboOrchardLab/robo_orchard_lab/dataset/horizon_manipulation/transforms.py:387)

这一步才是在训练取样过程中计算机器人各关节的空间位姿；转换 MCAP 时并不计算每个关节在 RGB 中的位置。
